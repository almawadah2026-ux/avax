## ⚠️ إفصاح أولاً — اقرأ هذا قبل أي شيء

| البند | الحقيقة |
|---|---|
| **لا تنفيذ حقيقي** | النظام **لا يتصل بأي منصة، ولا يملك مفاتيح API، ولا يرسل أوامر**. هذا محرّم دستورياً (المادة 0.2) ومفروض في الكود. |

| **المسؤولية** | على الإنسان. النظام ينتج صورة واضحة عن القرار، لا قراراً صحيحاً. |

## الفكرة في ثلاث جمل

1. **الوكلاء ليسوا أحراراً.** كل وكيل موظف بصلاحيات مكتوبة، وكل رأي يمر عبر محرك قوانين يرفضه آلياً إن خالف الدستور.
2. **القوانين مفروضة في الكود.** لا توجد مادة دستورية بلا سطر ينفّذها — الدستور نفسه يحمل جدول فرض، وقانون بلا فرض = قانون ميت (المادة 10.2).
3. **الامتناع نجاح لا فشل.** الديسك يمتنع عن ~70% من الدورات، وهذا مقصود: قرار بلا حافة أسوأ من لا قرار (المادة 0.4).

## البدء السريع

**لا اعتماديات خارجية — Python 3.11+ والمكتبة القياسية فقط.**

```powershell
# تشغيل دورة كاملة (بيانات اصطناعية سيناريو صاعد)
python -m avax_desk.cli --scenario bull --seed 11

# نفس الأمر مع PYTHONPATH صريح إن لم تُثبَّت الحزمة
$env:PYTHONPATH="src"; python -m avax_desk.cli --scenario bull --seed 11
```

### الأوامر الأساسية

| الأمر | الوظيفة |
|---|---|
| `python -m avax_desk.cli --scenario bull` | دورة كاملة على سيناريو محدّد (`bull`/`bear`/`chop`/`crisis`/`recovery`/`auto`) |
| `--seed 11` | بذرة العشوائية — نفس البذرة ⇒ **نفس النتيجة حرفياً** (تكرارية تامة) |
| `--live` | بيانات حيّة من CoinGecko و DefiLlama و Binance و alternative.me |
| `--capital 5000000` | رأس المال بالدولار (يؤثر على حجم المركز) |
| `--daily-pnl -1.6 --drawdown -8` | حقن خسارة يومية/تراجع لاختبار سلّم الإنذار |
| `--save-report reports/x.md` | حفظ التقرير النصي |
| `--json` | إخراج JSON كامل (يُغذّي سكربت التنسيق) |
| `--audit-roster` | تدقيق اتساق ملفات الوكلاء مع الكشف الرسمي |
| `--verify-journal` | التحقق من سلامة سلسلة الهاش في السجل |
| `--no-journal` | عدم الكتابة في السجل |

## الدستور في عشر مواد

القانون الكامل في [`CONSTITUTION.md`](CONSTITUTION.md). الخلاصة:

| المادة | الحكم | الفرض |
|---|---|---|
| **0** | الغرض: تحليل وقرار مكتوب. **يُحرَّم التنفيذ الحقيقي.** الامتناع مشروع. | `law.enforce_no_execution` |
| **1** | فصل السلطات الخمس: بحث ≠ تحقق ≠ قرار ≠ منع ≠ تسجيل | `law.validate_opinion` |
| **2** | عقد الرأي: 6 حقول إلزامية. **رأي بلا شرط إبطال = مرفوض آلياً.** | `Evidence.__post_init__` |
| **3** | هرمية أدلة من 7 مستويات + وسم البيانات القديمة | `law.arbitrate_evidence` |
| **4** | قانون التحقق (OOS، تكاليف، قدرة، Overfitting) + الإجماع التام = إنذار | `law.require_validation` |
| **5** | **سيادة المخاطر:** حق نقض مطلق + حدود رقمية + كيلي مقيد | `RiskEngine.evaluate` + `RiskVerdict.veto` |
| **6** | الرأي المخالف **يُسجَّل ولا يُحذف**. قرار بلا مخالف يُعاد. | `OrchestratorAgent._strongest_dissent` + `law.validate_decision_completeness` |
| **7** | سجل **غير قابل للتعديل** بسلسلة هاش + مراجعة بعدية | `JournalStore.verify_chain` |
| **8** | 10 جرائم محرّمة (اختلاق، تحيّز استرجاعي، تسريب، إخفاء خسائر…) | `PROHIBITED_PATTERNS` |
| **9** | الامتناع حق. 4 مستويات إنذار، والأحمر = إيقاف كامل فوري | `RiskEngine.risk_level` |

### الجولة الأولى — 14 بنداً كان معرّفاً بلا فرض فعلي
المادة 10.2 تنص: «قانون بلا فرض آلي = قانون ميت». أُصلحت كلها وأُضيف لكل إصلاح اختبار انحدار:

| # | الثغرة | الإصلاح |
|---|---|---|
| 1 | المستوى البرتقالي يصفّر الحجم بلا سبب نقض ⇒ قرار `LONG` بحجم `$0` | سبب نقض صريح عند مضاعف حجم صفري (المادة 9.3) |
| 2 | `DeskConfig.halt()` معرّفة و**بلا مستدعٍ** — الإيقاف ضمني لا فعلي | `RiskManagerAgent` يستدعي `halt()` عند المستوى الأحمر (المادة 5.4) |
| 3 | `FABRICATION_MARKER` و `HINDSIGHT_MARKER` — أخطر جريمتين بلا مسار فحص | `ComplianceAgent` يفحص **كل** الأنماط المحرّمة (المادتان 8.1 و8.2) |
| 4 | `capacity_checked = True` مُثبَّت بلا أي حساب | `capacity_analysis` حقيقي بقانون الجذر التربيعي (المادة 4.1) |
| 5 | المادة 8.3 (تسريب البيانات) بلا فحص إطلاقاً | `lookahead_audit` يقارن الإشارة التزايدية بالدفعية |
| 6 | `max_sector_concentration_pct` معرّف وغير مستخدم | مرشّح `sector_concentration_limit` في محرك المخاطر (المادة 5.3) |
| 7 | `stale_confidence_penalty` غير مستخدم وثابتة مضمّنة | `staleness_penalty()` تقرأ القيم من `Limits` (المادة 3.4) |
| 8 | المادة 9.3 «أصفر: تقلب مرتفع أو بيانات ناقصة» غير مفروضة | تخفيض 50% عند تقلب مرتفع أو اكتمال بيانات ناقص |
| 9 | `arbitrate_evidence` و `require_validation` معرّفتان بلا مستدعٍ | يُستدعيان في `ComplianceAgent` كتدقيق فعلي |
| 10 | المادة 7.1 «JSON + ملخص Markdown» — JSONL فقط | `JournalStore.write_markdown_summary` |
| 11 | المراجعة البعدية بلا أي واجهة | `--post-mortem` في CLI (المادة 7.3) |
| 12 | كيلي مقصوص عند حد المركز ⇒ قيد شكلي دائماً | سقف داخلي 30% ليكون كيلي مرشحاً حقيقياً مستقلاً (المادة 5.5) |

## تشغيل الوكلاء كنماذج لغوية (DSH Workflow)

كود Python هو العمود الفقري (البيانات، الرياضيات، فرض القوانين). ملف
`workflows/avax-desk.workflow.js` يشغّل **نفس الوكلاء الـ15 كنماذج لغوية حقيقية**:
كل وكيل يقرأ ملف تعريفه من `agents/` والدستور ويُنتج رأياً مهيكلاً بمخطط صارم.

```
المرحلة 0: وكيل البيانات يبني اللقطة السوقية
المرحلة 1: 8 وكلاء معرفة بالتوازي
المرحلة 2: التحقق + محامي الشيطان
المرحلة 3: وكيل المخاطر (حق النقض)
المرحلة 4: المنسّق يصدر القرار النهائي
```

استخدمه عبر أداة `workflow` مع:
```json
{ "symbol": "AVAX", "capitalUsd": 1000000, "quick": false }
```
أو مرّر لقطة جاهزة من `python -m avax_desk.cli --json` في الحقل `snapshot`.

> **تحقق فعلي:** شُغّل السكربت في الوضع السريع (7 وكلاء) على لقطة اختبارية.
> الوكلاء قرأوا الدستور وملفات تعريفهم، وأصدروا آراءً مهيكلة، و**امتنعوا بأنفسهم**
> لأن اللقطة كانت أقدم من 24 ساعة (المادة 3.4)، مع تبرير مفصّل من المنسّق.
> هذا اختبار قوي: القوانين مفروضة على النموذج اللغوي كما هي مفروضة على الكود.
>
> ⚠️ مرّر `snapshot.as_of` حديثاً (≤ 24 ساعة) وإلا فسيكون الامتناع هو المخرج الصحيح.

## القيود المعروفة (إفصاح صريح)

هذه ليست قائمة تحفّظ، بل خريطة لما **لا** يفعله النظام:

1. **لا يتحقق من صدق مضمون الأدلة** — يتحقق من وجود المصدر وطابعه الزمني، لا من صحته. اختلاق ذكي يمرّ.
2. **اختبار التحقق تقريب معلن** — `mini_backtest` يحاكي مكوّنات الديسك السعرية بإشارة مركّبة، ولا يطابق الإشارة المجمّعة تماماً. الوكيل 09 يصرّح بذلك في حقل الإبطال.
3. **بيانات المشتقات على AVAX رقيقة** — التقلب الضمني مُقدَّر لا من سطح أوبشن حقيقي، فالوكيل 06 يقيّد ثقته.
4. **تصنيف عناوين الأونشين على أفالانش أضعف من السلاسل الكبرى** — الوكيل 05 يذكر هذا في حقل المخالف.
5. **نماذج المخاطرة تفشل في الذيول** — VaR و CVaR مبنيان على تاريخ، والانفجارات خارج أي توزيع مُقدَّر.
6. **لا مراجعة بعدية تلقائية** — الآلية موجودة (`record_post_mortem`) لكنها تحتاج تشغيلاً دورياً لتفعيل تخفيض أوزان الوكلاء.
7. **البيانات الحيّة تحتاج شبكة** — عند الفشل يتراجع النظام للاصطناعي **ويعلن ذلك** في `meta.degraded_sources`.
8. **المنهج فيه فجوات موثّقة** — تدهور النموذج زمنياً، تخصيص الأداء بين الوكلاء، وتقدير أثر السوق في سيولة أفالانش منخفضة العمق.
